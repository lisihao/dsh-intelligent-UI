# Upgrade boundary

This independent repository owns the plugin, test fixtures and design records. No build or test resolves another project checkout. The historical npm package name and `$DSH_HOME/solar/intelligent-experience-platform` namespace remain unchanged for compatibility.

Pins live in `package.json` and `pnpm-lock.yaml`:

- `@openuidev/lang-core` and `@openuidev/react-lang` 1.0.2; `@openuidev/react-ui` and `react-headless` 0.18.1. Reuse `Renderer`, `openuiLibrary.extend/prompt`, Markdown/Table, ThemeProvider and form/action APIs in `presentation.ts`, `client.ts` and `style.ts`. DSH supplies React/ReactDOM 18.3.1.
- `@modelcontextprotocol/ext-apps` 2.0.4 with SDK `core/client/server` 2.0.0. `mcp-connector.ts`, `mcp-view.ts`, `mcp-proxy.ts` and `mcp-host.ts` use public tool/resource metadata, UI MIME, AppBridge manual mode, initialization/notifications, mediated tool calls and teardown. SDK 2 values do not replace the host's SDK 1 objects.
- All DSH peers remain 0.2.1-rc.2, Cordis 4.0.5. A host-baseline update is a separate scoped task.

1. Inspect the fixed upstream release and applicable license notices before changing pins; install published artifacts with lifecycle scripts disabled.
2. Run component/parser/streaming/action/state tests with host React. Verify production browser output contains no additional React instance or automatic OpenUI development inspector.
3. `build-css.mjs` uses PostCSS and prefix-selector to scope OpenUI token roots and its generic text utilities; vendor-namespaced component/portal selectors stay intact. Inspect this boundary when upgrading CSS. Confirm native light/dark mode and stylesheet cleanup. The adapter removes automatic OS-dark token media rules so the explicit host theme remains authoritative.
4. Run real local MCP transport and bridge tests, tool visibility/guard/session tests, receipt replay fences, and the distinct-origin proxy checks. Inspect custom `dsh-app://app` origin support against the actual official app; HTTP-browser proof is separate.
5. Build and run the scratch built-package acceptance; inspect real rendering and on/off/disable behavior in the installed official app before claiming compatibility. Preserve raw sources and persisted settings/state through upgrade.
6. Refresh THIRD_PARTY_NOTICES.md and include upstream/transitive license notices required by bundled runtime code.

Carried upstream source patches: **none**. Host-specific behavior is confined to the adapters above. Do not patch the installed app, monkey-patch DSH services, or copy upstream source into a maintained fork inside this package.

Automatic content presentation uses pinned `unified@11.0.5`, `remark-parse@11.0.0` and `remark-gfm@4.0.1` in `content-analysis.ts`, plus OpenUI `MarkDownRenderer.options.remarkPlugins/components`, `LineChart`, `BarChart`, and `IconWrapper` in `presentation.ts`. These public APIs preserve GFM AST source offsets, table cells and safe Markdown rendering. No custom parser or upstream patch is carried. Upgrades must pass content-analysis and presentation regressions (source values, units, mixed-period rejection, escaped pipes, tables, streaming and raw mode), then render the actual JSON report via `tools/real-output-demo.mjs` in Desktop. The display policy is a local deterministic subset; it does not call a model or infer values from arbitrary prose.

Column/subgroup selection remains a thin adapter over the same unified/GFM AST. `analyzeTableCharts` selects multiple plans with original row/column provenance; `analyzeTable` and the first Markdown `.plan` remain compatibility conveniences. `presentation.ts` renders plans independently through existing OpenUI charts and exposes original selected cell strings, basis and exclusions. Upgrade checks must cover multi-period columns, unit separation, totals, missing values and approximate-source labels, then replay the unchanged private research report. No new dependency or upstream patch is introduced.

## Source-derived layouts and React Flow

The unchanged published `@xyflow/react@12.12.0` (MIT) is pinned in this package and its lockfile; it is already used by the repository native-collaboration plugin. Its distributed license and runtime dependency notices are retained in THIRD_PARTY_NOTICES.md. `flow-view.ts` uses public ReactFlow, node/edge, Handle, Controls and viewport APIs with host-shared React18. It adds source labels, adjacency emphasis, pause/reduced-motion handling and read-only interactions; no upstream source or app patch is carried. `build-css.mjs` scopes the published vendor stylesheet to `.dsh-experience .iexp-flow`; `flow-view.css.ts` supplies the measured presentation roles. Upgrade checks must exercise pointer/keyboard selection, viewport pan/zoom, animation pause/reduced motion, safe long labels, cycles and exact source access in browser and installed DSH.

`content-layout.ts` consumes the existing unified/remark GFM AST and Zod: explicit arrows or contextual sequential steps, source headings, strict graph JSON, task-state records/tables and long named records. Numbered findings do not imply a process. Graph parsing errors remain visible with original content. `layout-views.ts` renders read-only grouped tasks, one object detail region, and actual heading links; a small chapter fan uses bounded native SVG spokes and original heading counts with a complete linear alternative; long or dense outlines retain the conventional index. Source data remains authoritative and the shared display-mode control is unchanged.

`comparison-view.ts` is a thin semantic meter adapter for 2–6 compatible, nonnegative, single-series categories. Published OpenUI0.18.1 exposes no custom mark-shape or endpoint-value renderer on its BarChart API, so the adapter preserves original labels/values with a common measured scale. It does not calculate or display new percentages, rank colors, totals or wins. Negative/multiseries/dense plots and time series retain maintained OpenUI charts. Test comparison eligibility, zero values, original endpoint strings and narrow wrapping.

Source-preservation, streaming, actual graph error recovery, board input order and shared raw/comparison regressions live in content-layout, flow-view, comparison-view and layout-presentation tests. Browser fixtures can read the unchanged research report and real outputs from `tools/real-layout-output.mjs`; these local artifacts and any research data must stay outside Git.

`elkjs@0.12.0` is consumed unmodified using its EPL-2.0 option, with complete distributed license and source availability URLs in THIRD_PARTY_NOTICES.md. `flow-layout.ts` calls the published bundled ELK layered algorithm, fixed ports and returned edge sections for node positioning and obstacle-avoiding routes. `flow-view.ts` uses public BaseEdge for those routes; the adapter only rounds the library’s returned bends. This replaces the handwritten SCC column layout after an actual source graph revealed a long edge passing through an unrelated node. No ELK build, Java runtime, external Worker URL or runtime network fetch is required. The pinned package is installed normally with other npm dependencies and scripts disabled. Upgrade checks must use the real import graph, verify route segments do not intersect unrelated node interiors, inspect label placement and test pending/error states as well as pause/focus/source preservation.

## Theme packages and the ThoughtDAG exception (2026-10-31)

`src/theme-contracts.ts` validates v1 data-only packages using the existing pinned Zod dependency; built-in JSON manifests use exactly the same contract. `theme-runtime.ts`, `appearance.ts` and the scoped styles resolve presentation tokens, while `store.ts` keeps selection/import/removal in the existing revision queue and atomic settings document. On schema changes retain old settings without a `theme` field and test concurrent changes, unknown versions, import/remove/restart, source disclosures and original page restoration. The existing installation backup is required before downgrading to an older strict-schema binary.

`src/thoughtdag-theme.ts` is a narrow, user-authorized extension of the earlier iframe exclusion, inspected against Solar ThoughtDAG 0.1.0-dev.1. Its known wrapper and same-origin `/thoughtdag/` mount admit an owned stylesheet mapping the SPA's semantic variables and bounded card/node classes. No ThoughtDAG file, attribute, preference, storage record or business API is changed. On a ThoughtDAG upgrade inspect the mount, semantic variables and root layers again; run `tests/thoughtdag-theme.test.ts` for lazy load, navigation, original DOM/handlers/state, cross-origin exclusion and disposal, then perform native canvas theme/off checks. Do not broaden the bridge to unknown frames.

No toolbar position, font size, graph geometry or owner source changes. On owner upgrades recheck this bounded heading selector and title visibility.
