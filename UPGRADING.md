# Upgrade boundary

This independent repository owns the plugin, test fixtures and design records. No build or test resolves another project checkout. The historical npm package name and `$DSH_HOME/solar/intelligent-experience-platform` namespace remain unchanged for compatibility.

Pins live in `package.json` and `pnpm-lock.yaml`:

- `@openuidev/lang-core` and `@openuidev/react-lang` 1.0.2; `@openuidev/react-ui` and `react-headless` 0.18.1. Reuse `Renderer`, `openuiLibrary.extend/prompt`, Markdown/Table, ThemeProvider and form/action APIs in `presentation.ts`, `client.ts` and `style.ts`. DSH supplies React/ReactDOM 18.3.1.
- `@modelcontextprotocol/ext-apps` 2.0.4 with SDK `core/client/server` 2.0.0. `mcp-connector.ts`, `mcp-view.ts`, `mcp-proxy.ts` and `mcp-host.ts` use public tool/resource metadata, UI MIME, AppBridge manual mode, initialization/notifications, mediated tool calls and teardown. SDK 2 values do not replace the host's SDK 1 objects.
- All DSH peers remain 0.2.1-rc.2, Cordis 4.0.5. A host-baseline update is a separate scoped task.

1. Inspect the fixed upstream release and applicable license notices before changing pins; install published artifacts with lifecycle scripts disabled.
2. Run component/parser/streaming/action/state tests with host React. Verify production browser output contains no additional React instance or automatic OpenUI development inspector.
3. `build-css.mjs` uses PostCSS and prefix-selector to scope OpenUI token roots and its generic text utilities; vendor-namespaced component/portal selectors stay intact. Inspect this boundary when upgrading CSS. Confirm native light/dark mode and stylesheet cleanup. The adapter removes automatic OS-dark token media rules so the explicit host theme remains authoritative.
4. Run real local MCP transport and bridge tests, tool visibility/guard/session tests, receipt replay fences, and the distinct-origin proxy checks. Inspect custom `dsh-app://app` origin support against the actual official app; HTTP-browser proof is separate.
5. Build and run the scratch built-package acceptance; inspect real rendering and on/off/disable behavior in the installed official app before claiming compatibility. Preserve raw sources and persisted settings/state through upgrade.
6. Refresh THIRD_PARTY_NOTICES.md and include upstream/transitive license notices required by bundled runtime code.

Carried upstream source patches: **none**. Host-specific behavior is confined to the adapters above. Do not patch the installed app, monkey-patch DSH services, or copy upstream source into a maintained fork inside this package.

Automatic content presentation uses pinned `unified@11.0.5`, `remark-parse@11.0.0` and `remark-gfm@4.0.1` in `content-analysis.ts`, plus OpenUI `MarkDownRenderer.options.remarkPlugins/components`, `LineChart`, `BarChart`, and `IconWrapper` in `presentation.ts`. These public APIs preserve GFM AST source offsets, table cells and safe Markdown rendering. No custom parser or upstream patch is carried. Upgrades must pass content-analysis and presentation regressions (source values, units, mixed-period rejection, escaped pipes, tables, streaming and raw mode), then render the actual JSON report via `tools/real-output-demo.mjs` in Desktop. The display policy is a local deterministic subset; it does not call a model or infer values from arbitrary prose.

Column/subgroup selection remains a thin adapter over the same unified/GFM AST. `analyzeTableCharts` selects multiple plans with original row/column provenance; `analyzeTable` and the first Markdown `.plan` remain compatibility conveniences. `presentation.ts` renders plans independently through existing OpenUI charts and exposes original selected cell strings, basis and exclusions. Upgrade checks must cover multi-period columns, unit separation, totals, missing values and approximate-source labels, then replay the unchanged private research report. No new dependency or upstream patch is introduced.

## Canvas UI on-device effects (development candidate)

The catalog and source hashes are pinned in `src/canvas-catalog.ts` and `src/canvas-source-manifest.ts` to Canvas UI commit `a04a99b235299ee79a123a16ccb2e6cf9da74b6b`. Effects need the network on first use after a Host restart.

The original Canvas UI MIT + Commons Clause terms, including the restriction on redistributing components themselves, are retained in `assets/Canvas-UI-LICENSE.md` and generated module notices; Three.js notice is included too. Do not replace those terms with this repository's MIT license or publish a copy of the upstream component bundle. Development discovery points to upstream sources. On upgrade, review the upstream license and change log, update the immutable commit and all source hashes together, check the declared source imports and factory names, and re-run source integrity, authenticated route, actual browser, lifecycle and native Desktop checks. `canvas-object-view.ts` is a local integration rather than a patch to an upstream component.
