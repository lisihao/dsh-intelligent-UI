# Executable component and material runtime acceptance

## Scope

This source delivery preserves the default-off block-layout experiment and configurable Option+Command+I shortcut. It adds same-ID component registration, exact input discovery, source binding and actual rendering for the existing library; it does not install into the owner's active official Desktop, merge a branch, change a package version or publish a release.

The decision path is source parsing → legal candidate bindings → Jev family/partition/component selection → exact-ID/input/freshness validation → registered consumer. Stable partitions preserve all eligible leaves. The first phase asks only frame/style questions; it does not duplicate the old block presentation choices. Automatic mode omits the current display theme and compiler-internal material defaults. No diversity reward, hidden top-K or fallback from a failed component decision to an old inferred selection is introduced.

## Review and remaining boundaries

An independent read-only integration review identified one TuffUI lifecycle defect: a changed component ID could reuse the same mount ID and retain the old component or fail its update. The consumer now includes component identity in its binding key, disposes/remounts a distinct component, and retains the frame for same-ID prop updates. Focused transport regressions also cover a prior error, unchanged-ID no-retry behavior and waiting for the replacement iframe's own load event. A separate 20-case test against the real packaged catalog/type schemas checks automatic Markdown compatibility: source-exact prose remains eligible; unsupported code/math/directory content is excluded from the plain-message adapter; plain table text, empty cells and decoded escapes/entities are preserved while rich table cells are excluded. These exclusions apply only to adapters that cannot render those semantics, not to the block's full candidate set or explicit supplied component props. The review itself ran no browser, build or model.

TuffUI still explicitly rejects three opaque optional prop contracts; it does not invent a generic object implementation. Canvas retains its fixed-source first-use network route. Rune requires actual WebGPU and retains readable source with a named diagnostic when unavailable. These limits are inputs to component eligibility.

A development helper unintentionally synchronized the local Rust `stable` toolchain to 1.99.1 during the initial build. The default toolchain name stayed `stable`; its prior version was not captured, so no guessed downgrade was attempted. The helper now uses explicit pinned toolchain paths and does not resynchronize the default. This is a build-environment event, not a runtime plugin dependency.

Installed official Desktop acceptance, merge, package/release publication and real-model selection of the later library bridge were not run. Private input files, model sessions, prompts, screenshots, credentials and runtime capability URLs remain outside Git.
