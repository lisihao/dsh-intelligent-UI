# Experimental source-bound block layout compiler

This experiment addresses the whole-document selection boundary observed in the five-file Markdown review. It is opt-in and defaults to disabled when its saved setting is absent. It is a source development feature, not an installed-app or real-model acceptance claim.

## Contract

The pipeline is source parsing → compiler-owned block references and eligible candidates → one scoped Jev Decisions request → exact-choice and source validation → existing renderers. Jev chooses registered presentations; it supplies no rewritten source, new metrics, graph relations, HTML, CSS or JavaScript.

`adaptive.blockLayout` controls the entire compiler path. The existing `adaptive.enabled`, takeover and Jev feature gates still apply. Turning the experiment off restores the existing whole-output selection path and prevents an old compiled response from being adopted. `adaptive.blockLayoutShortcut` stores a configurable keyboard binding; its default is `Alt+Meta+KeyI` (Option + Command + I). A shortcut change alone does not change the decision fingerprint. Keyboard handling is client-owned and disposed with the plugin.

## Composition levels

The document retains one coherent theme and a reading frame. Each source-owned block can choose an eligible presentation and component set. A source table can stay a table, supply a historical chart or become a task board only when the existing analyzer validates the corresponding source contract. Explicit relationships may use the existing React Flow path. Loading, short text updates, live series, illustrations and object effects retain their existing input and browser requirements.

Research inspection is separate from the reading frame and block decisions. It must not suppress a neighboring flow, table, heading navigation or chart. Its option description explains that it adds report-local inspection and does not independently verify sources or execute AI organization.

The compiler targets bounded top-level source units. It splits prose at the finest source-heading depth that fits the complete block budget, and falls back to complete parent sections when necessary. Adjacent prose without a source heading may share a block, but is never excluded from selection. Every unit, including ordinary prose and code, receives an explicit presentation question. `reading`, `cards` and `disclosure` are executable source-bound treatments; validated data adds concrete table, chart, board, record or flow recipes. A choice is a complete renderer recipe, rather than an `auto` instruction to run the previous heuristic selector. Nested nodes keep their complete original AST and inherit their containing unit's selected treatment; the model does not independently select each nested sentence.

Experimental continuous reading groups intact source blocks into Paper chapter/figure regions. It does not apply the legacy paragraph-to-caption rearrangement inside an already selected block. The nonexperimental Paper transform is unchanged.

Markdown is rendered from the complete source document. Compiler offsets use UTF-16 positions matching the Markdown AST, not separately reparsed text fragments. Reference definitions and footnotes therefore remain document-scoped. Normalized tool text blocks use a source path as well as local Markdown offsets. Table eligibility is derived from the complete Markdown analysis and bound back to the exact source table, so nearby units, comparison prohibitions and section boundaries are not lost when identifying a block. Unrecognized content remains readable; source order, source strings, units and qualifications remain available.

## Candidate boundary and explanations

Candidates come from executable adapters with a normal rendering consumer, validated against actual source and runtime capabilities. The catalog's development archive, metadata-only items and blocked effects do not become executable merely by appearing in the catalog. Existing installed themes and compiled component sets remain available subject to user locks and compatibility. Every block wrapper supplies a compiled ThemeCard consumer. Automatic style mode offers native, soft-relief, clear-glass and mechanical-outline material per block; selected style mode retains the user's manual material lock. Theme packages remain selectable through the global theme question; an ASCII chart recipe may explicitly bind a compatible local ASCII theme. Irregular or gapped time series retain a renderer that preserves their original spacing and gaps; incompatible general-chart choices are not offered for those blocks. This is not a claim to automatically run every archived Uiverse or Canvas component.

The experimental registry also covers the 14 existing Canvas HTML effects, the isolated Bend/Hex Float interfaces and Particle Scroll through an actual source-bound consumer. These are optional visual copies beside a complete visible source, not replacements for text, code or data. Eligibility requires bounded noninteractive source, browser support, no streaming and no reduced-motion restriction; Magnify additionally requires explicit text-free decoration. Unsupported geometry/resources and execution errors remain visible. Metadata-only Canvas entries remain excluded. Object effect eligibility uses supported assets and actual renderer requirements; the old coding/project-management domain recommendations do not prohibit a model's explicit selection.

Local failure defaults stay in the coordinator and are omitted from the experimental model request. Recipe metadata also omits inactive auto fields and the local native material placeholder; each block explicitly binds its material to its independent component-set question. These local executor values are not model constraints or recommendations. A pure-prose document may use source sections for continuous reading, and a long document may expose its complete heading index; the old mixed-media and 100-heading recommendation thresholds remain confined to the nonexperimental path.

The model receives descriptive affordances and tradeoffs rather than reason codes alone. Returned identifiers are checked against the exact questions sent. Singleton capability axes are filled locally; presentation choices for prose and code are never singleton or pre-fixed. Experimental model questions contain no `auto` option. Missing or invalid model choices are errors, not successful heuristic decisions. Every block reference is compiler-owned and is bound to the complete source revision and saved settings. Invalid, stale, unsupported or over-limit programs retain the local source view and surface a reason; they do not trigger an automatic paid retry.

The view can show the selected block adapter and local eligibility evidence. These explanations are generated from recorded source/candidate facts, not represented as textual reasoning returned by the Decisions API. Evaluation checks suitability and source coverage, not artificial diversity across five files.

## Verification boundary

Focused tests cover disabled compatibility, mixed-block candidates and rendering, exact source references, invalid choices, batched requests, stale-setting rejection, shortcut handling and durable settings. The final source gate and browser observations are recorded separately from any real Jev or official Desktop acceptance. No account, saved Jev route or installed plugin is changed by development tests.
