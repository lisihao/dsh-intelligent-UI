# Experimental source-bound block layout compiler

This experiment addresses the whole-document selection boundary observed in the five-file Markdown review. It is opt-in and defaults to disabled when its saved setting is absent. It is a source development feature, not an installed-app or real-model acceptance claim.

## Contract

The pipeline is source parsing → compiler-owned block references and eligible candidates → one scoped Jev Decisions request → exact-choice and source validation → existing renderers. Jev chooses registered presentations; it supplies no rewritten source, new metrics, graph relations, HTML, CSS or JavaScript.

`adaptive.blockLayout` controls the entire compiler path. The existing `adaptive.enabled`, takeover and Jev feature gates still apply. Turning the experiment off restores the existing whole-output selection path and prevents an old compiled response from being adopted. `adaptive.blockLayoutShortcut` stores a configurable keyboard binding; its default is `Alt+Meta+KeyI` (Option + Command + I). A shortcut change alone does not change the decision fingerprint. Keyboard handling is client-owned and disposed with the plugin.

## Composition levels

The document retains one coherent theme and a reading frame. Each source-owned block can choose an eligible presentation and component set. A source table can stay a table, supply a historical chart or become a task board only when the existing analyzer validates the corresponding source contract. Explicit relationships may use the existing React Flow path. Loading, short text updates, live series, illustrations and object effects retain their existing input and browser requirements.

Research inspection is separate from the reading frame and block decisions. It must not suppress a neighboring flow, table, heading navigation or chart. Its option description explains that it adds report-local inspection and does not independently verify sources or execute AI organization.

The first experimental compiler targets top-level semantic units and coalesces adjacent passive prose. Nested rich content without its own compiled binding stays in native document form; it is not advertised as an independently model-selected component.

Markdown is rendered from the complete source document. Compiler offsets use UTF-16 positions matching the Markdown AST, not separately reparsed text fragments. Reference definitions and footnotes therefore remain document-scoped. Normalized tool text blocks use a source path as well as local Markdown offsets. Table eligibility is derived from the complete Markdown analysis and bound back to the exact source table, so nearby units, comparison prohibitions and section boundaries are not lost when identifying a block. Unrecognized content remains readable; source order, source strings, units and qualifications remain available.

## Candidate boundary and explanations

Candidates come from executable adapters with a normal rendering consumer, validated against actual source and runtime capabilities. The catalog's development archive, metadata-only items and blocked effects do not become executable merely by appearing in the catalog. Existing installed themes and compiled component sets remain available subject to user locks and compatibility. A component-set question requires an actual compiled control/card consumer. Irregular or gapped time series retain a renderer that preserves their original spacing and gaps; incompatible general-chart choices are not offered for those blocks. This is not a claim to automatically run every archived Uiverse or Canvas component.

The model receives descriptive affordances and tradeoffs rather than reason codes alone. Returned identifiers are checked against the exact questions sent. Singleton choices are filled locally. Every block reference is compiler-owned and is bound to the complete source revision and saved settings. Invalid, stale, unsupported or over-limit programs retain the local source view and surface a reason; they do not trigger an automatic paid retry.

The view can show the selected block adapter and local eligibility evidence. These explanations are generated from recorded source/candidate facts, not represented as textual reasoning returned by the Decisions API. Evaluation checks suitability and source coverage, not artificial diversity across five files.

## Verification boundary

Focused tests cover disabled compatibility, mixed-block candidates and rendering, exact source references, invalid choices, batched requests, stale-setting rejection, shortcut handling and durable settings. The final source gate and browser observations are recorded separately from any real Jev or official Desktop acceptance. No account, saved Jev route or installed plugin is changed by development tests.
