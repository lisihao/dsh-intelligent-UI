# Tuff UI component integration

The owner-supplied short link resolves to https://tuffui.com/, whose official source is https://github.com/yurigdesigner/tuffui. The inspected revision is `378f3eaac693c693d2ec845baf38bf6c0488cb37`, MIT. The project was cloned and read before its install/build/test scripts ran.

The registry contains 76 visual entries (69 UI components and seven screen blocks) plus three supporting entries (theme, motion tokens and a mock-run hook). Support entries are dependencies, not visual choices. The registry is copy-source distribution rather than a standalone npm UI package. This integration must preserve an immutable source/upgrade boundary and original notices; do not silently copy and maintain unrelated upstream files.

The owner project uses shared React 18/Tailwind 3; this source declares React 19.3/Tailwind 4, plus aliased shadcn components, motion and icon packages. The implemented adapter uses an isolated React 19/Tailwind 4 renderer with its own dependency realm; it does not import that source into the host React 18 tree. Do not change DSH's host React, modify the installed app or report an untested source import as working.

Every visual component needs an executable adapter and explicit data/action schema before it is called Jev-selectable. Its candidate must bind supplied or observed source data, describe suitability and prerequisites, and dispatch to the actual component. Tool approvals, retry/stop/restore, MCP authorization and background agent controls retain host ownership; UI selection cannot execute these actions. Mock/demo run state is never evidence of a real agent execution. Whole-screen blocks are not ordinary prose replacements. Missing host seams remain visible rather than invented.

The upstream agent-question registry metadata contains an invalid dependency inferred from a source comment. The installer must not execute this metadata blindly. Source pins, resolved dependency closure, licenses, build output and actual browser controls/default/narrow bounds require verification. All 76 entries and their executable/blocked/unadapted status must be tracked; a metadata-only catalog addition does not satisfy the owner's all-components requirement.

## Implemented and verified boundary — 2026-11-06

All 76 source entries are registered through their exact `tuffui:<id>` consumers and recursive public prop schemas. The runtime bundle contains eight hashed assets and the complete 83-package license closure. Three opaque optional source-prop contracts remain explicitly unsupported: the date field's calendar object and two drop-zone rules. Supplying them is rejected; no unknown-object bypass is used. Source runtime/approval screens require actual supplied snapshots and host-owned actions rather than demo runs.

Automatic source mapping covers plain-cell source tables, valid JSON, supported code, source links, source-exact plain completed/streaming paragraphs and ChartCard when the existing analyzer supplies exactly one validated chart plan. The original StreamingMessage parser is not a full Markdown renderer; automatic projection excludes rich Markdown, code, math and directory syntax. DataTable string cells are projected from AST text values, including empty cells and decoded Markdown escapes/entities; rich cells remain eligible for compatible renderers rather than being stringified. Explicit supplied component props remain available. Multi-plan or ambiguous chart mappings are excluded with a named reason. Distribution samples, gauge targets, graph domains and other absent facts are not fabricated to enable a visual. Explicit valid source props remain available for the other components.

The real React 18 consumer ran through the production ComponentRuntimeHost CSP/CORS/CORP and a different-origin opaque frame. The parent could not read the child document. A DataTable row click returned the exact synthetic source row through its one local action ID; a ChartCard legend changed locally without a host action. Both 1440/390 checks retained viewport width. These are clearly labelled synthetic transport/rendering checks, separate from the five actual-model document outputs and from installed Desktop acceptance. The initial entry-query 404 was fixed in the fixed asset server and is covered by an HTTP regression.

Public reproducible fixture sources and commands live in `tools/tuffui/browser-proof`; compiled parent pages, runtime capability URLs and screenshots remain private temporary artifacts.

The consumer also covers same-mount-ID component replacement: a changed component ID disposes the old mount before mounting the new one; same-ID prop updates retain the frame. A prior component error does not poison a distinct component, and a replacement iframe must deliver its own load event before receiving a mount. These transport lifecycle regressions do not introduce automatic retries for an unchanged failed component.
